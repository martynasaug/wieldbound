WHY glTF RATHER THAN THE FBX IN THE SAME PACK
  ~2.7x smaller for the identical model (Orc: 1250 KB vs 3395 KB), the texture
  atlas is embedded in a bufferView so each file is standalone, and it needs
  none of the material-rebuilding and UV-flip correction the FBX path below
  requires. The client loads both formats; `name` carries the extension.

  This pack is distributed from a Google Drive folder, which cannot be fetched
  programmatically — it was downloaded manually. Worth knowing if these ever
  need re-acquiring.

TEXTURES

../textures/*.png      Shipped with the packs above. Material names mostly
                       match file names; the loader resolves exact, then
                       `<name>_Texture`, then a prefix match, and falls back
                       to a flat colour (see assets.ts).

NOTE ON flipY

Textures keep three.js's default flipY (true). The usual advice for FBX is to
force it false — doing that here put every UV island on the wrong part of the
atlas and rendered the warrior's steel plate as the brown leather sitting
directly above it in the sheet.
